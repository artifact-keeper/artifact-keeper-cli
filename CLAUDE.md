# CLAUDE.md — artifact-keeper-cli

## Overview

`artifact-keeper-cli` is the official CLI/TUI for Artifact Keeper, an enterprise artifact registry. The binary is named `ak`.

## Build & Development Commands

```bash
# Build
cargo build

# Run
cargo run -- --help

# Lint
cargo fmt --check
cargo clippy --workspace -- -D warnings

# Test
cargo test --workspace

# E2E tests, against a local backend at the version in API_VERSION (needs Docker)
./tests/start-backend.sh
cargo test --test 'e2e_*' -- --include-ignored --test-threads=1
./tests/stop-backend.sh

# Release build (LTO, stripped)
cargo build --release

# Regenerate SDK from OpenAPI spec
cargo run -p xtask -- generate

# Verify SDK is up-to-date
cargo run -p xtask -- generate --check

# Write ROUTES.json from a backend checkout at the pin (../artifact-keeper), or verify it
cargo run -p xtask -- routes
cargo run -p xtask -- routes --check

# The coverage gate: every route has a command or a reason
cargo run -p xtask -- coverage --check

# Does each registry line tell the truth? Runs the real binary against a mock server
cargo test --test registry_contract -- --include-ignored

# `ak pkg` against each format's real client, in containers. Not in CI: it pulls one image per client
tests/pkg-clients.sh
```

## Architecture

### Workspace Layout

```
Cargo.toml             # Workspace root (members: sdk, xtask)
src/                   # CLI binary (artifact-keeper-cli, bin: ak)
  main.rs              # Entry point (tokio async)
  cli.rs               # clap derive: Cli struct, Command enum, GlobalArgs
  error.rs             # miette diagnostics (AkError enum)
  transport.rs         # Plain-HTTP instance URL checks and warnings
  registry.rs          # Which command covers which server route. Add a line for each route a new command calls
  output/mod.rs        # OutputFormat (table/json/yaml/quiet), render helpers
  config/
    mod.rs             # AppConfig (TOML), InstanceConfig, load/save
    credentials.rs     # Keychain credential storage
  commands/
    mod.rs             # Module declarations: the full list of command modules
    <group>.rs         # One module per command group (auth, repo, artifact, scan, ...)
    setup/mod.rs       # auto-detect + per-ecosystem config (npm, pip, cargo, etc.)
    pkg/               # `ak pkg <format>`: one file per format
    tui.rs             # TUI dashboard (ratatui)
    client.rs          # SDK and raw HTTP client construction
    helpers.rs         # Shared table, prompt and parsing helpers
    chunked_upload.rs  # Resumable uploads for `artifact push`
    device_flow.rs     # Device authorization login
    snapshots/         # insta snapshots for the commands' tests
sdk/                   # Generated API SDK (artifact-keeper-sdk)
  src/lib.rs           # Re-exports progenitor_client + generated types
  src/generated_sdk.rs # Generated by `cargo xtask generate` (144K lines, DO NOT EDIT)
xtask/                 # SDK generation tool
  src/main.rs          # OpenAPI 3.1→3.0 conversion + Progenitor code generation
```

### SDK Generation

The SDK is generated from `../artifact-keeper-api/openapi.json` using Progenitor (Oxide Computer). `API_VERSION` pins the API version: check out `artifact-keeper-api` at `v$(cat API_VERSION)`. xtask fails unless `API_VERSION`, the spec's version and the `sdk/Cargo.toml` version all match.

The xtask handles OpenAPI 3.1 → 3.0 conversion (nullable types, oneOf/anyOf patterns, content type schemas) before passing to Progenitor, and works around what Progenitor can't generate:

- 2 endpoints using multipart/form-data are skipped and called over raw HTTP (`KNOWN_SKIPS`). Generation fails on any other skip.
- A `text/xml` request body is generated as `text/plain`.
- Different 2xx bodies on one operation become a `oneOf` named `<operationId>_outcome`.
- Fields required by the pinned API but absent on the previous server minor are generated as `Option` (`NOT_REQUIRED_ON_PREVIOUS_MINOR`). Update that list when the pin moves to a new minor.

To regenerate: `cargo run -p xtask -- generate`. To check: `cargo run -p xtask -- generate --check`, which the `SDK Drift` CI job runs.

### Coverage gate

The `Coverage` CI job holds the CLI to "anything curl can do". It isn't a required check yet.

- `ROUTES.json` is the backend's route table, read from its source by `xtask routes`, with a trailing slash removed from each path. `OCI_ROUTES.json` is the OCI surface that the backend routes in a fallback handler, kept by hand, with `not_routes` for what the OCI spec has and the server doesn't, which the gate and `tests/e2e_pkg_oci.rs` watch. Regenerate `ROUTES.json` whenever `API_VERSION` moves.
- `xtask coverage --check` reads those, the spec, and the registry from `ak __registry`. Each route needs a line in `src/registry.rs` or a class exclusion there. It prints the per-tag table.
- `COVERAGE_PENDING.json` is empty, and stays that way: the gate fails if a route is added to it.
- Every field in a covered operation's schema has to be in that route's `binds`, or in `FIELD_OPT_OUTS` with a reason.
- `xtask/src/raw_layer.rs` reads `src/commands`, and fails on a function that calls an SDK operation with a JSON response without `raw::capture`, or that prints with `output::render`, unless its `OPT_OUTS` says why. It checks the source, not behaviour.
- `tests/registry_contract.rs` runs each registry line against a mock server, and fails if the command doesn't send that request, or if a listed field doesn't reach the server. A new command that it can't drive needs an entry in that test's `hints` or `preflight`.

### Version policy

The first two numbers of the CLI version are the server version it's built for. The last number is the CLI's own and doesn't match the server's patch number: `ak` 1.11.0 is built from API 1.11.11. New commands may ship in CLI patch releases (1.11.x). `ak` supports servers on that minor and the one before it, and `ak doctor` warns outside that range. `API_VERSION` also sets the backend image for E2E.

### Key Patterns

- **GlobalArgs**: Shared options (format, instance, no_input) extracted from `Cli` before command dispatch to avoid borrow checker issues with partial moves
- **OutputFormat**: All commands use the `--format` flag (table/json/yaml/quiet) for output
- **Instance resolution**: flag `--instance` > config `default_instance` > error
- **Config path**: `$AK_CONFIG_DIR` or `~/.config/artifact-keeper/config.toml`
- **Error handling**: `miette::Result` throughout, `AkError` with diagnostic codes and help text. `AkError::exit_code` maps each variant to the exit code in `ak --help`, and `main` applies it. `ak api` keeps its own table. `Usage` is what the user typed, `Local` a failure on this machine, `ConfigError` ak's own configuration
- **Async**: All commands are async via tokio
- **`ak api`**: `src/commands/api.rs` sends any request. The instance's token goes only to the instance's own origin. A new route is reachable through it from day one, before it has a command
- **`ak pkg`**: `src/commands/pkg/`, one file per format. A format's wire protocol isn't in the spec, so these use `pkg::wire::Wire` over raw HTTP and build what that format's client sends. Plain GETs have no helper: they're `ak api`
- **SDK errors**: `sdk/src/error.rs`, swapped into generated code by xtask. `{e}` gives `<status>: <server message>` and can't print a header. Use `sdk_err` for SDK calls and `helpers::raw_err` for raw HTTP
- **Raw JSON**: `--format json` and `yaml` must print the response as received. Wrap the SDK call in `artifact_keeper_sdk::raw::capture` and print with `output::render_raw`, or `helpers::emit_mutation_raw` for a mutation. New commands use these rather than `output::render`
- **Repository and artifact arguments**: `helpers::resolve_repo_id` and `resolve_artifact_id` take a key or a UUID. Use them rather than `parse_uuid` for any repository parameter

- **Confirmations**: a destructive or security-decision command takes `--yes` and `-y`, and calls `helpers::confirm_action` before it sends anything. `--no-input` means never prompt and isn't an answer: `--yes` is the only consent. Without it that's an error, exit code 2, and nothing goes out. A prompt that has to read from the server first calls `helpers::ensure_can_confirm` before those reads. `tests/registry_contract.rs` checks every command with `--yes` refuses this way. Elsewhere `--no-input` just disables prompts

### Environment Variables

| Variable | Purpose |
|----------|---------|
| `AK_FORMAT` | Default output format |
| `AK_INSTANCE` | Override default instance |
| `AK_NO_INPUT` | Never prompt, as `--no-input` does: `1`, `true` or `yes`. `0`, `false`, `no` or empty leave it off. Destructive and security-decision commands then need `--yes` |
| `AK_COLOR` | Color mode (auto/always/never) |
| `AK_CONFIG_DIR` | Override config directory |
| `AK_TOKEN` | API token (alternative to keychain) |
| `AK_CREDENTIAL_STORE` | `file` skips the OS keychain and uses the credentials file only |
| `AK_CA_CERT` | Path to a PEM file with additional root CA certificate(s) to trust (same as `--ca-cert`) |
| `NO_COLOR` | Standard no-color flag |
